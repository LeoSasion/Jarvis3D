# JARVIS 交互 UI 改良计划

2026-10-03 · 基于 `e8834ba` 的现状审查。目标是让桌面、知识图谱和 Agent 在异常状态下也清楚说明「当前是什么、下一步能做什么、哪些内容会被发送」。保持 [`DESIGN.md`](../../DESIGN.md) 已确定的黑色 HUD、橙色状态强调、现有图形风格和 Windows 可恢复边界。

## 审查范围与证据

- 在 1280×720 的本地浏览器预览中，用 4 篇合成笔记走通桌面 → Explore 搜索 → 选中笔记 → 本地读取摘录 → 加入上下文 → Agent 草稿 → 模拟回答 → `[S1]` 回看，并查看设置的「交互界面」「图谱」分区。预览明确标记为 `BROWSER PREVIEW`，没有使用个人 Vault 或真实服务商。
- 同时审查前端状态模型、Host 启动/退出路径及现有验证记录。下文把浏览器中看到的现象与由代码推断的风险分开；原生失败页、触屏和混合 DPI 仍需实机验收。
- 现有优点应继续保留：发送前明确确认摘录、回答中的来源快照、2D/3D 独立相机、键盘图谱导航、参数 A/B 比较、原生任务栏的失败回退。

## 界面结构原则

- **桌面状态只回答当下问题**：顶栏继续承担运行和 Agent 状态；长期的故障与回退提供一个可追溯的入口，短暂成功提示保持轻量。右侧遥测继续展示真实或明确标记的模拟状态。
- **探索页把下一步放在选择旁边**：搜索、选中笔记、定位镜头、读取摘录形成同一个可见操作区；选中详情和摘录篮不因左侧长列表滚动而完全消失。
- **Agent 让回答占主要阅读面积**：发送前展开精确的待发送来源；发送后收为一行可展开的状态。引用回看按需覆盖或展开，不长期挤占对话；会话入口和保存状态留在窗口标题区。
- **设置从常用到高级**：语言、主题、任务栏安全选项先出现，Profile、参数和配置恢复有清楚的页内锚点。表单标签、键盘焦点和错误提示随状态变化保持一致。

## 首条主线：有来源的知识提问

1. **找到**：Explore 搜索栏显示当前查询、加载状态与结果数。点击结果后，节点选择和「定位到图中」保持一致。
2. **确认**：本地摘录显示路径、绝对行号、字数与快照时间；篮子固定显示 `1/2` 或 `2/2`，图谱重新扫描后标记旧版本快照并允许重新读取。
3. **发送**：Agent 草稿上方列出本次确实要发送的 `[S1]` / `[S2]` 与行范围；点击「发送」才分享。取消或失败后来源状态仍与下次请求载荷一致。
4. **核对**：回答引用可点开本轮快照并定位行，无法解析的引用明确显示「未核验」。用户向上阅读时，新 token 不夺走滚动位置。
5. **续聊**：会话库入口与保存状态留在标题区；恢复旧对话时说明历史摘录仅供回看，重新使用必须显式附上。

## 验收门槛

- **状态一致**：对 `staged / submitting / running / complete / error / aborted / restored` 建立 UI 文案与实际发送载荷的对照测试；任何显示「将发送」的来源都必须在下一次请求中，任何历史来源都不能被悄悄带入。
- **恢复可达**：利用现有 `verify-native-failure-paths.ps1` 注入启动超时和 WebView 崩溃；在原生失败页通过鼠标和键盘退出，验证 Windows 任务栏恢复。Full 模式退出等待需显示持续状态并阻止重复提交。
- **布局与输入**：用相同合成数据检查 1280×720、1920×1080、2560×1440；加测键盘全流程、200% 缩放、减少动态、长回答与长文件名。触屏及多屏混合 DPI 以真实设备结果为准。
- **视觉稳定**：沿用固定图谱场景的浏览器/WebView2 回归，保证镜头定位、面板避让和来源抽屉不会改动已认可的节点、信号、发光或系统恢复行为。

实现切入点：Agent 来源状态在 `frontend/src/agent-context-model.js` 与 `frontend/src/components/AgentConversationWindow.jsx`；搜索、摘录篮在 `frontend/src/graph/KnowledgeBrowser.jsx`；图谱镜头在 `frontend/src/graph/GraphCameraNavigation.jsx`；原生失败与退出在 `host/Jarvis.Host/MainWindow.xaml.cs`。对应验证优先扩充现有前端状态测试、`scripts/verify-native-failure-paths.ps1` 和双语 `scripts/verify-renderer-smoke.ps1`。

先完成 P0 的状态与恢复承诺，再把 P1 的「搜索 → 摘录 → 回答 → 核对」做成连续路径；P2 在这条路径稳定后处理设置密度、输入方式与首次使用。每个改良包应独立提交和验证，避免大规模换肤掩盖交互回归。
